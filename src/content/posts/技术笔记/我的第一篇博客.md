## 为什么写博客

一直想有一个属于自己的地方，不依赖任何平台，能自由地记录学习和生活。

选型对比了一圈，最终定了 **Astro + Firefly**，理由很简单：

| 方案 | 优点 | 缺点 |
|------|------|------|
| Hexo | 生态成熟 | 构建慢，主题同质化 |
| Hugo | 构建极快 | 模板语法学习成本高 |
| Astro | 现代化、支持多框架组件 | 静态博客主题较少 |

Firefly 这个主题功能丰富 — 追番、动态、相册、音乐播放器都有，省去了自己折腾的功夫。

## 部署踩坑

### 1. Node.js 版本

Firefly 要求 **Node.js >= 22**，我之前装的 20.x，`pnpm install` 直接报错。

```bash
# 用 nvm 切换版本
nvm install 22
nvm use 22
```

### 2. 图片路径规则

这是最容易踩的坑，配置文件里的图片路径有两种：

```ts
// 以 "/" 开头 → 从 public/ 目录读取，不做优化
avatar: "/assets/images/avatar.webp"

// 不以 "/" 开头 → 从 src/ 目录读取，Astro 自动优化
avatar: "assets/images/avatar.avif"
```

> ⚠️ 搞反了图片就显示不出来，一开始我在这里卡了半天。

### 3. 构建流程

`pnpm build` 的完整流程：

1. 生成 LQIP（图片模糊占位）
2. Astro 构建
3. 裁剪未使用的静态资源
4. 字体子集化
5. 内联脚本压缩
6. Pagefind 索引生成

整个流程自动化，基本不用管。
